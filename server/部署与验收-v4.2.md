# v4.2：飞书录音日记与 Obsidian 每日归档

构建标识：`2026-09-09-feishu-recording-journal-v4.2`。

## 系统边界

手机通过 HTTPS 调用另一台电脑上的 AILearningOS 后端。飞书回调、AI 摘要、数据库与 Obsidian 文件全部在该后端运行。Claw 只负责部署服务器更新，不参与录音处理、AI 路由或 Codex 登录。

## 本版内容

1. Journal 新增录音日记光盘柜，按日期展示飞书录音豆每日总结，支持左右循环滑动、箭头切换、点击阅读和手动刷新。
2. 每段转写继续使用账号当前选择的 DeepSeek 或 ChatGPT-Codex 总结；同一天的结果按北京时间聚合。
3. 每日记录保存到 SQLite `notes`，同时幂等写入 `data/obsidian-vault/<userId>/Recording Daily/`。
4. 重复 `recording_id` 更新当天原记录；缺少 ID 时使用转写文本 SHA-256，避免重试制造重复内容。
5. 保留 v4.1 的 Codex 登录防抖、Canvas、OSS 会话读取、账号隔离和五小时额度自动回切。

飞书桥接字段和限制见包内 `录音日记.md`。飞书只发送录音就绪事件而没有转写正文时，接口返回 `accepted=false`，需要桥接取得转写后重新提交。

## 部署

使用 `AILearningOS-server-windows-x64-v4.2.zip` 更新实际服务器，例如 `D:\AI-自学OS\server`。

1. 核对实际 `server.exe`、PID、8080 监听归属、计划任务动作和运行账号。
2. 停止自动拉起并正常停止旧服务；完整备份 SQLite、WAL/SHM、旧程序和脚本。
3. 保留 `data`、`AILO_SECRETS_MASTER_KEY`、`FEISHU_WEBHOOK_TOKEN`、`FEISHU_VERIFICATION_TOKEN`、代理和 Cloudflare 配置。
4. 覆盖包内 `bin\server.exe`、两个 `sqlite3.dll` 和 `start-server.ps1`。
5. 使用实际后端服务账号通过 `start-server.ps1 -CodexCommand "C:\codex\codex.exe"` 启动，并保持计划任务指向该脚本。

## 验收

```text
GET /health -> 200 OK
GET /version -> build = 2026-09-09-feishu-recording-journal-v4.2
GET /version -> codex_gateway_enabled = true
GET /version -> recording_daily = asia-shanghai-idempotent-obsidian-v1
```

使用测试用户和不含敏感信息的测试转写向既有 `/api/feishu/<userId>/webhook` 投递：

1. 首次投递返回 `accepted=true`，Journal 刷新后出现当天日期光盘。
2. 点击光盘能看到摘要、学习要点和待处理内容。
3. 同一 `recording_id` 修改文本后重投，光盘仍为一张，当天段数不增加且内容更新。
4. 检查 `data/obsidian-vault/<userId>/Recording Daily/` 存在当天 Markdown，并且 `00 Index.md` 只有一个对应链接。
5. 用另一用户投递时，双方数据库笔记和 Obsidian 目录互不混合。

部署完成后仍需使用真实飞书回调和真实账号当前 AI 路由完成线上验收。日志与验收输出不得包含飞书 token、LearningOS Bearer、ChatGPT token、完整转写或 `auth.json`。
