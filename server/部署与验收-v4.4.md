# v4.4：Codex 额度耗尽的 DeepSeek 回退修复

构建标识：`2026-09-10-codex-quota-fallback-v4.4`。

## 此版本修复什么

1. 当官方 Codex App Server 返回 `reached the limit`、`resource exhausted`、`too many requests`、`429` 等额度用尽信号时，已开启自动回切且已配置 DeepSeek Key 的账号会立即临时使用 DeepSeek。
2. 单词 AI 队列不再把额度错误当普通 warning；它会保存 DeepSeek 路线和官方重置时间，因此手机关闭后仍可继续处理。
3. 同时有短周期与长周期额度时，后端会等待所有已耗尽窗口恢复后再切回 Codex，避免短周期到点后反复失败。
4. 手机设置页会阻止“没有保存 DeepSeek Key 却切换到 DeepSeek”的假成功，并明确说明换同一 ChatGPT 账号的 Codex 模型不会生成新额度。

## 部署边界

手机只通过 HTTPS 调用另一台运行 `server.exe` 的 Windows 后端电脑。ChatGPT/Codex 登录态、额度读取、SQLite 和 DeepSeek Key 都在那台电脑。Claw 如被使用，只是独立的部署机器人，不参与 AI 路由或额度消耗。

## 安全升级步骤

使用 `AILearningOS-server-windows-x64-v4.4.zip` 更新实际后端。

1. 确认计划任务、运行账号、`server.exe`、8080 监听和数据目录；备份 SQLite、WAL/SHM、旧程序和脚本。
2. 保留 `data`、`AILO_SECRETS_MASTER_KEY`、DeepSeek 加密密文、Canvas/飞书配置、Cloudflare 和现有 `data/codex-users`。不要删除或复制其中的 Codex 登录态。
3. 覆盖 `bin\\server.exe`、`bin\\sqlite3.dll`、`lib\\sqlite3.dll` 与 `start-server.ps1`。
4. 使用实际服务账号执行：

```powershell
.\\start-server.ps1 -CodexCommand 'C:\\codex\\codex.exe'
```

5. 确认计划任务仍调用该脚本和同一绝对 Codex 路径，再恢复 Cloudflare 通道。

## 验收

```text
GET /health  -> 200 OK
GET /version -> build = 2026-09-10-codex-quota-fallback-v4.4
GET /version -> codex_gateway_enabled = true
GET /version -> codex_quota_fallback = all-windows-aware-deepseek-fallback-v2
```

用一个测试账号完成下面的真实流程：

1. 在 DeepSeek 设置中保存并测试可用 API Key。
2. 在设置中开启“额度恢复后自动切回 Codex”，并切到 ChatGPT-Codex。
3. 当官方额度真实耗尽时提交一次 AI 单词补全或录音总结；它应转为 DeepSeek，而不是连续重试 Codex。
4. 重新打开手机，确认当前路线仍显示 DeepSeek，且有官方重置时间。
5. 到重置时间后，后端只在所有报告为耗尽的限额窗口都有剩余额度时切回 Codex。
6. 在 ChatGPT-Codex 操作表中换模型，确认设置保存；若额度仍耗尽，应用应提示改用 DeepSeek 或等待重置，而不是声称模型会带来新额度。

不要把 LearningOS Bearer、Canvas/飞书 token、DeepSeek Key、ChatGPT token、`auth.json` 或任何用户学习内容写进部署日志或提交到 Git。
