# AILearningOS 服务器部署指南

> 本目录保留早期 v3.7 部署结构供历史参考。当前正式版本是 v3.9；请使用 `server/Codex登录修复-v3.9.md` 以及 GitHub Release 中的 v3.9 后端包，不要把本页的 v3.7 构建标识作为当前验收标准。

当前部署包版本：`2026-09-04-codex-gateway-launch-v3.7`。本版本加入按账号隔离的手机 ChatGPT/Codex 设备码登录、Codex 额度读取、服务端每 2 秒增量同步 OSS 会话到 Obsidian，以及每台设备独立的 Bearer 会话。手机登录成功后完整翻页读取 Codex App Server 的 `model/list` 并自动选择当前账号可用模型；历史同步按官方协议启用实验 API，登录后的账号、模型、额度、对话和 AI 请求复用同一个用户隔离的 App Server 进程。新包提供 `start-server.ps1`，保证计划任务或服务启动时真正启用 Codex 网关并固定 Codex 可执行文件路径。旧 `gpt-5.4` 配置自动迁移，DeepSeek Key 只作为用户手动切换时的备用配置，仍按账号加密保存。

APP 的 AI 模型源是账号级全局开关。词库补全、对话笔记、邮件摘要、飞书摘要、每日课程计划和 AI Chat 全部使用用户当前手动选择的 `DeepSeek V4` 或 `ChatGPT-Codex`；任一路径失败时都不会自动切换到另一条路径。

AILearningOS 后端与 Claw 是两个独立系统。真正承接手机 HTTPS 请求、启动 `codex app-server`、隔离登录态、调用模型并消耗 Codex 额度的是 AILearningOS 后端 `server.exe`。Claw 不属于后端，也不参与 Codex 登录、请求转发、凭据保存或模型调用。

## 已有服务器原地升级

如果目标服务器已经运行 AILearningOS 后端，请在后端主机替换 `bin/server.exe`、`bin/sqlite3.dll` 和兼容旧目录的 `lib/sqlite3.dll`。`bin/sqlite3.dll` 必须与 `server.exe` 放在一起，否则独立 EXE 无法启动：

1. 停止旧的 AILearningOS 后端进程或计划任务；
2. 备份原有 `data/ai_study_os.sqlite3`；
3. 保留原 `data` 目录、`AILO_SECRETS_MASTER_KEY` 和代理配置；
4. 用本包中的三个程序文件覆盖旧文件，并复制根目录的 `start-server.ps1`；
5. 不再直接启动 `bin/server.exe`，改为从包根目录运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start-server.ps1`；计划任务也必须指向这个脚本；
6. 访问 `/version`，确认 `build` 为 `2026-09-04-codex-gateway-launch-v3.7`，且 `codex_gateway_enabled` 为 `true`；
7. 检查 `/version` 的 `ai_features`，确认六类 AI 能力均为 `selected_provider`。

不要把本包解压到 `data` 目录，也不要重新生成 `AILO_SECRETS_MASTER_KEY`。部署包不含生产数据库、API Key、ChatGPT 凭据、主密钥或 Cloudflare 凭据。

## 手机 Codex 登录：必需的服务器配置

手机不能在 APK 内启动 Codex，因此 AILearningOS 后端必须在 **实际运行 `server.exe` 的目标主机** 启动官方 `codex app-server`。这完全是后端自身的运行能力，不依赖 Claw。不需要增加新的公网端口，也不需要暴露 WebSocket；手机仍然只通过你已有的 Cloudflare HTTPS 域名访问本服务。

1. 在运行 `server.exe` 的同一个 Windows 服务账号下安装官方 Codex CLI，并确认命令可用：`codex --version`。
2. 从部署包根目录运行 `.\start-server.ps1 -DataDirectory 'C:\AI_OS_Server\data' -Port 8080`。脚本会为本次服务进程设置 `AILO_CODEX_GATEWAY_ENABLED=1`、绝对数据目录和 `AILO_CODEX_EXECUTABLE`，并在缺少 Codex CLI 时直接停止并给出错误。
3. 让运行服务的 Windows 账号对 `data\codex-users` 有读写权限，其他普通账号不应有读取权限。这里的匿名子目录包含 Codex 的受管登录态；不要把它做成静态文件、不要写入日志、不要放入普通备份或公开网盘。
4. 确认 Cloudflare Tunnel 仅将 HTTPS 请求转到本服务；不要映射或公开 Codex App Server 的任何端口。设备码页面由 `auth.openai.com` 承载。
5. 升级 APK 后，手机点“使用 ChatGPT 登录”会显示设备码；在系统浏览器完成授权，再回应用点击“完成后继续”。服务器会将该登录态绑定到该 ChatGPT 账号的独立目录和该手机的独立会话。
6. 登录后日志中的 `Codex OSS sync persisted ...` 表示服务端已将新增用户/助手正文写入 `data\obsidian-vault\<userId>\Codex Raw`。手机退到后台也不会停止这条归档链路。

> 如果日志显示网关已启用但登录无法开始，最常见原因是 `server.exe` 所在的服务账号找不到 `codex` 命令。请在**同一个服务账号**下执行 `codex --version`，不要只在你的交互式管理员终端中验证。

Windows 使用 npm 全局安装时通常同时生成 `codex.ps1` 与 `codex.cmd`。本包的启动脚本会明确选择可供后台子进程启动的 `codex.exe` 或 `codex.cmd`，并先执行 `--version` 验证。Claw 或服务器管理员只需要安装 CLI，不要执行服务器全局 `codex login`；每位用户应在手机中发起设备码登录，登录态由 AILearningOS 后端写入各自隔离的 `data\codex-users` 目录。

你好！这是一份提供给服务器维护人员的部署手册。
本项目由一个独立的 Windows 可执行文件 (`server.exe`) 组成，无需在服务器上安装 Dart 环境，直接运行即可。

## 文件说明
- `bin/server.exe`: AILearningOS 的核心后台服务程序。
- `bin/sqlite3.dll`: SQLite 运行库，必须与 `server.exe` 位于同一目录。
- `lib/sqlite3.dll`: 为旧版部署脚本保留的兼容副本。
- `start-server.ps1`: 推荐的后端启动入口；负责验证 Codex CLI，并为每次启动持续应用 Codex 网关配置。
- `config.yml`: Cloudflare Tunnel 的配置文件模板。

## 部署步骤

### 第一步：启动后端服务
1. 将当前文件夹（包含 `bin/server.exe`）放在服务器上的任意合适位置（例如 `C:\AI_OS_Server\`）。
2. 运行 `.\start-server.ps1`（如果防火墙弹窗提示，请允许网络访问）。不要绕过脚本直接启动 `bin\server.exe`，否则 Codex 网关默认保持关闭。
3. 程序启动后，控制台会输出：`Server listening on port 8080`，并会在同级目录下自动创建一个 `data` 文件夹用于存放 SQLite 数据库。

> 💡 **进阶建议**：为了让服务器重启后自动运行，可以使用 Windows 的“任务计划程序”创建开机自启任务，执行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\AI_OS_Server\start-server.ps1`，不要直接执行 `bin\server.exe`。

---

### 第二步：配置 Cloudflare Tunnel (cloudflared)
我们需要通过 Cloudflare Tunnel 将 `http://localhost:8080` 暴露给 `os.georgehan0514.top`。

#### 1. 准备 cloudflared
请确保服务器上已下载 `cloudflared.exe`，并建议将其放置在 `C:\cloudflared\` 目录下。
**请以“管理员身份”运行 PowerShell 并进入该目录。**

#### 2. 登录并创建隧道
```powershell
# 1. 登录 Cloudflare 账号（会弹出浏览器授权）
.\cloudflared.exe tunnel login

# 2. 创建隧道（名字可以叫 ai-os-tunnel）
.\cloudflared.exe tunnel create ai-os-tunnel
```
* **注意**：第二步执行完后，屏幕会打印一串 `UUID`。请把这个 UUID 记下来。

#### 3. 绑定域名
```powershell
.\cloudflared.exe tunnel route dns ai-os-tunnel os.georgehan0514.top
```

#### 4. 修改配置文件
打开我提供给你的 `config.yml` 文件，将里面的内容修改为服务器实际的路径和 UUID：
- 替换 `<你的隧道UUID>` 为刚才生成的 UUID。
- 替换 `<服务器用户名>` 为当前服务器登录的 Windows 用户名（或者是你凭据实际所在的路径）。

修改完成后，将 `config.yml` 复制到 `C:\cloudflared\` 目录下。

#### 5. 测试与注册为系统服务
测试隧道是否正常工作：
```powershell
.\cloudflared.exe tunnel --config C:\cloudflared\config.yml run
```
如果没有报错，按 `Ctrl + C` 退出。接着，将其注册为 Windows 后台服务，以便开机自启：

```powershell
.\cloudflared.exe service install
```
然后你需要修改一下注册表，告诉服务加载你的配置文件：
1. `Win + R` 运行 `regedit`。
2. 找到 `HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Services\Cloudflared`。
3. 修改 `ImagePath`，值为：`C:\cloudflared\cloudflared.exe --config C:\cloudflared\config.yml tunnel run`。
4. 在“服务”(`services.msc`) 中找到 `Cloudflared agent` 并启动它。

### 第三步：验证
使用手机流量（不要连同一局域网的 Wi-Fi），在浏览器中访问：
`https://os.georgehan0514.top/health`

如果网页显示 `OK`，部署即宣告大功告成！

## Claw 自动更新（独立、可选）

Claw 只负责把经过验证的后端发布包复制到服务器，并执行与人工升级相同的停止、备份、替换、启动和健康检查步骤。它是独立的自动更新机器人，不是 AILearningOS 后端的一部分。Codex 接入不得调用 Claw，也不得把 ChatGPT 登录态、Codex 凭据、Bearer 会话或 AI 请求交给 Claw。没有 Claw 时，管理员仍可按本指南独立部署并运行全部后端和 Codex 功能。
